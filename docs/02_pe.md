# The Processing Element

## From Dot Product to Hardware

Matrix element `C[i][j]` is a dot product:

$$
C_{ij} = \sum_{k=0}^{3} A_{ik} \cdot B_{kj}
$$

For a single dot product, feed paired elements and accumulate:

```text
a = [2, 3, 4]
b = [5, 6, 7]

acc = 2×5 + 3×6 + 4×7 = 10 + 18 + 28 = 56
```

## PE Block Diagram

```text
        a_in
          │
          ▼
      ┌────────┐
b_in ─►│   PE   │
      │        │
      │ a × b  │
      │ + acc  │
      └───┬────┘
          │
    a_out, b_out, acc
```

The PE does three things each cycle:
1. **Pass through** `a_in → a_out` (operand propagation)
2. **Pass through** `b_in → b_out` (operand propagation)
3. **Multiply and accumulate** `acc += a_in × b_in`

## RTL Mapping

Every line in `rtl/pe.sv` maps directly to the diagram:

```systemverilog
assign product = $signed(a_in) * $signed(b_in);  // a × b

always_ff @(posedge clk) begin
    if (rst) begin
        a_out <= '0;   // reset propagation
        b_out <= '0;
        acc   <= '0;   // reset accumulator
    end else begin
        a_out <= a_in;              // pass A through
        b_out <= b_in;              // pass B through
        acc   <= acc + product;     // accumulate
    end
end
```

| RTL line | Architecture action |
|----------|-------------------|
| `a_out <= a_in` | A flows to the next PE in the row |
| `b_out <= b_in` | B flows to the next PE in the column |
| `acc <= acc + product` | Running sum of products |

## Stage 2 Preview: Why Propagation?

Once your PE works, wire **two PEs in a chain**:

```text
A ──► PE ──► PE ──► ...
```

You'll discover that operands must propagate — the second PE needs the `a_out` from the first. That's why every PE passes data through, not just accumulates.
